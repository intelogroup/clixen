# Conversation History & Compaction

The harness manages chat history via a per-chat sliding window and thread-safe persistent store implemented in `store/conversation.py`.

**2026-07 redesign**: the full history is always kept — in memory (LRU-evicted per `MAX_CACHE_SIZE`, reloaded from disk on next access) and on disk (`store/sessions/*.json`) — `_store` is never destructively rewritten. What's actually SENT to the model per call (`trim_to_budget()`) is a separate, much smaller rolling view: a continuously-updated 1-2 sentence summary of everything older than `KEEP_RECENT_TURNS`, plus those recent turns verbatim — not the old behavior of filling any remaining token budget with more raw older turns. This keeps the cloud payload roughly constant size regardless of how long a conversation has grown, instead of it silently ballooning until a threshold fired. (Prior design's `MAX_TURNS=80` / `budget*0.8` compaction gate meant a chat could sit at, say, 50 turns / 10K raw tokens for a long time with zero compaction, still sending everything every call.)

## Key Parameters
- `KEEP_RECENT_TURNS = 10` (5 user + 5 assistant turns) — turns always sent verbatim; must stay even (pair-aligned).
- `_summary_cache` (per chat_id: `{"summary": str, "compacted_through": int}`) — the rolling summary of everything older than the window. Persisted to `store/sessions/_summary_cache.json` + LanceDB (`save_session_summary`, source `session_memory`) so it survives restarts and outlives the raw window (see Raw TTL below).

## Design Rules & Mechanics
1. **Continuous folding, not threshold-gated**: `compact_old_turns()` runs after every turn (same call sites as before) and folds any newly-slid-out turns into the summary unconditionally — no token-budget or turn-count gate. `compacted_through` tracks how many older turns are already folded so each call only summarizes the new slice, not the whole backlog again.
2. **Full history never lost**: compaction only ever writes to `_summary_cache`, never to `_store` — the complete raw history is always available via `get()`/on disk, independent of what gets sent to any model.
3. **Path Resolution & Collision Protection**: Session files are persisted to `store/sessions/`. The filename is formatted with a SHA-256 suffix of the `chat_id` (e.g. `test_split_<hash>.json`) to guarantee uniqueness and prevent collision between similar IDs (e.g. `session/1` vs `session:1`).
4. **Context Window Overflow Protection**: `trim_to_budget()` normally returns `[summary_turn?] + recent`. If even that doesn't fit the budget (unusually long recent turns), it trims `recent` from the oldest end, keeping the summary and the newest turns first.
5. **Merge, don't flatten**: each fold prompts the summarizer with the EXISTING summary plus only the NEW exchanges since, producing one updated summary — never re-summarizes from scratch.

## Fold model & output format (2026-07-09)
`_call_cloud_chat_raw()` runs the fold on local `qwen3.5:4b` first (`think=False`, `num_ctx=4096`, `keep_alive=-1`), cloud DeepSeek as a fallback only on local error/empty response — never the silent-omission path. Live-tested: 1.5-5s/fold, no timeouts.

Output is a **flat `owner: fact` semicolon-separated list** (e.g. `user: lives in Lisbon; user: owns dog Biscuit`), not freeform prose. This was a deliberate fix, not the original design: prose summaries let qwen3.5:4b weld unrelated attributes from different owners into one noun phrase across successive folds (live-caught: `"peanut-allergic teal dog Biscuit"` — the dog's name, the user's allergy, and the user's favorite color, fused into one claim; a separate run produced `"the assistant's favorite color is teal"`, swapping the fact to the wrong party). A shared prose clause gives a small model room to blend subjects; one-clause-per-fact removes that shared clause. Confirmed via a 36-turn live test: 0 entity-merge errors post-fix vs. 2 different fabricated-attribution bugs across 3 earlier attempts (prompt-only "never merge facts" instructions did not hold).

Two corruption guards wrap every fold call in `_fold_new_turns_into_summary()`, reject-and-retry once, `compacted_through` held back (not advanced) if both attempts fail so the slice retries next fold instead of vanishing:
- `_has_leak_markers()` — regex for reasoning-trace/formatting leakage (`**`, `"(N characters)"`, `"Wait,"`, `"Let me"`, `"Note:"`) that surfaced despite `think=False`; a local `_strip_think()` is also applied defensively to the raw model output (inlined in `conversation.py`, not imported from `src.g4l.core.utils` — that cross-package import only resolves when the caller's process happened to put the project root on `sys.path`, true for `telegram_bot.py`, **false for `whatsapp_bot.py`**, which was silently degrading every WhatsApp fold to the cloud/omitted fallback until caught and fixed 2026-07-09).
- `_has_role_swap()` — narrow regex for the assistant being assigned a personal fact it never stated (`"assistant's ..."`, `"assistant is/has/prefers/..."`) — the one attribution-swap failure mode caught live. Deliberately narrow: an earlier blanket "every capitalized word must appear in the source" grounding check was dropped after it false-positived on valid inferences (flagged "Portugal" as ungrounded from "Lisbon" alone), burning both retries into `"[Earlier conversation omitted]"` on a clean fold.

**Concurrency guard — overlapping-fold race (2026-07-09)**: `compact_old_turns()` runs inside harness.py's per-chat `get_lock()`, but that lock only covers the spawn — the fold itself (network call + `_summary_cache` write) runs unlocked in the background thread. Live-reproduced: rapid back-to-back messages for the same chat (a burst, a fast typer) spawn overlapping fold threads; when a slower earlier one finishes after a faster later one, its write clobbers the newer state and `compacted_through` **regresses** (reproduced: went 2→1), silently re-processing or losing already-folded turns. Fixed with `_folding_in_progress: set[str]`, checked/set under `_summary_lock` in `compact_old_turns()` before spawning — a chat with a fold already in flight skips spawning a second one; the next call's larger `new_slice` picks up whatever the skipped call would have folded, so nothing is permanently lost, just deferred one turn. Verified live: pre-fix run showed a regression at t=3.5s; post-fix rerun of the same rapid-fire scenario showed zero regressions.

**Messaging-process gotcha**: Telegram/WhatsApp run under one launchd job (`com.clixen.messaging`, `messaging_supervisor.sh`), a long-lived process separate from `com.clixen.core` — editing `store/conversation.py` (or anything it imports) needs `launchctl kickstart -k gui/$(id -u)/com.clixen.messaging` to take effect for live bot traffic, independent of restarting `core`. `core.py`'s `_run_telegram_bot()` is dead code — never wired into `_TARGETS`, so `core` restarts don't touch messaging at all.

## Raw TTL + summary reconciliation (2026-07-31)

- **Sliding 24h raw TTL**: `expire_old_raw()` deletes `store/sessions/*.json` (except `_summary_cache.json`) whose mtime is older than `RAW_TTL_SECONDS` (24h). mtime = last append, so active chats keep raw history as long as they're used; dormant chats expire. Chats resident in the in-memory `_store` are exempt. Fold summaries (disk + LanceDB `session_memory`) survive the raw window — durable memory outlives the raw transcript.
- **Dual-source recall**: `recall_block()` now searches `user_memory` AND `session_memory` (fold summaries), so facts from expired/old chats surface automatically as labeled `[earlier conversation <id>: ...]` bullets — previously fold summaries were only reachable via explicit `search_sessions()`.
- **Specialist memory**: all specialists (research/read/write/audio/video/scraper/data/path/transport) prepend `mem_block_for(query)` to their system prompt. Form specialist is a deterministic fast-path (no LLM loop) and deliberately skips it.
- **3h reconciliation** (`jobs/handlers/memory_verify.py`, workflow `memory_verify`, interval 3h): (a) enforces the raw TTL, (b) for each chat with a fold summary + raw on disk, asks the cloud model whether the summary missed critical facts and merges gaps back into `_summary_cache` + LanceDB. Uses DeepSeek v4-flash primary, Claude Haiku fallback — the fold model (qwen3.5:4b) measured too weak for gap detection (returned NO_CHANGE on an obvious passport+allergy miss). Output passes the same corruption guards (`_has_leak_markers`, `_has_role_swap`) as folds.
